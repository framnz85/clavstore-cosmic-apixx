# Threat assessment and validation plan

No production attacks, dependency installs, service startups or native inference were performed in Stage 11-A. Existing Stage 10 **428 passing tests are historical evidence and were not rerun**. Eight new in-memory probes ran against public functions/fixture data only; some intentionally demonstrate limitations, not successful defenses. source-probes.json records the distinction. No new test source, executable script, runtime adapter, vector index or fixture image was created.

## Review evidence versus test assertions

P01 default JWT metadata; P02 no-exp rejection; P03 bounded authorized fixture token; P04 wrong-key rejection. P05 pin-shape gap; P06 detector-quality loss through validateResponse → resolveReview → Stage 10 guard; P07 missing slug projection; P08 noncanonical temp-prefix condition. All probes are non-mutating public-interface calls or pure path math using fixture-only keys/data; they do not implement a fix or prove deployed security. Production Mongo/Redis/native images/network/actual users were not accessed. The 428 historical results remain historical, not 436 freshly passing integration tests.

## Stage 11-B regression plan (PROPOSED)

Batch A: import/construction with both gates false must not load real models/dbconnect/cache or parse/process passwords. Test prefix order before existing auth, current route base, generic failures and rate/schema bounds. Credential cases: plaintext comparison against fixture legacy storage only, no client hash acceptance, no query operators, duplicate email/store, inactive/deleted user/store/reseller, role/order permission and wholesale revoked, wrong subject/scope/issuer/audience/key/algorithm, no-exp/expired/future/excessive TTL, end-of-await expiry. Preserve old login endpoints/token/cart behavior. No token/credential output in test logs.

Batch B: factory composition tests using explicit fixture repositories, no require-cache or module-export patches. Verify actual exported router registration rather than only createRouter with unused options; new response retains IDs/flags/metadata; old confirm never called; current search/review records are scoped/whitelisted and include slug. Exercise real Stage 2 validateImage → bridge → Stage 7 sniff/Stage 3 decode in isolated tests; serialized fixture AI initially, then separately approved native fixture session tests. Negative conformance cases from P05/P06, wrong sidecar revision/generation/expiry/tenant and poisoned current rows must fail. Native pipeline cap remains ten. Test client/main/worker leases and cleanup separately, no falsely inferred remote completion.

Batch C: jsdom test new wrapper/link with all flags false, permitted/denied roles, empty cart direct route, selected slug/tenant mismatch and expired scanner-only session. User click camera only, late camera/scan/search responses discarded, EXIF/oriented overlays, unknown/manual corrections/quantities, repeated identical SKUs and flavors, current stock/price/slug collision. Spy only declared local dependencies/fixtures, never install global runtime injections. Assert no dispatch/updateCart/saveCartOrder/localStorage writes. Old route/Barcode/ImageCapture imports/navigation and POS payment/save button remain unchanged.

Before and after each approved batch: byte/SHA/symlink baseline, exact diff allowlist, targeted new tests then all frozen Stage 2–10 suites through existing isolated runners with NEW /tmp outputs. Test artifacts/cache must stay outside protected files; retain counts and run provenance. Never import server.js, legacy controllers or model modules to run a unit test; those can start listeners/DB/cache. Stage 11-A deliberately did not rerun broad suites because no source was changed and the task is documentation-only. Historical logs were read, not relabeled as new execution.

Batch D: separate authorization for non-production browser + actual HTTP/TLS/cancellation/proxy and read-only fixture-store E2E, disabled-by-default config and a review-only credential. No production MongoDB/Redis/cart or existing index rebuild. Real device/light/occlusion/unknown/variant dataset evaluation, target-host load and rollback drills require their own approved access/data scope. Lack of real labels/VPS evidence remains BLOCKED. No end-to-end staging was performed during this review.
