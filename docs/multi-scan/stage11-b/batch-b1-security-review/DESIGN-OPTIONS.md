# Minimality and schema decision gates

Current schema supports narrow read-time denial by deleting a user, changing to customer, removing membership or pausing a store. It does not supply independently trustworthy per-user enabled/revoked state, immutable tombstones or an authorization epoch. If every writer and consumer is secured, current-data rechecks can enforce those specific denials without schema migration; a still-valid JWT can otherwise become usable again if matching access is restored, and a physical deletion has no distinction from never-existing identity. Do not describe this as durable credential revocation or generalized account activation.

Two NEW alternatives require explicit approval; neither describes existing fields:

- **Smallest schema delta after complete writer hardening:** add proposed authorizationStatus (default revoked, enum active/disabled/revoked) and authorizationVersion (positive monotonic integer) to canonical User, update status/role/membership/credential fields and version in the same atomic scoped User mutation, and require current status/version on every scanner consumer. This reduces cross-document coordination. However ALL profile/import/app/credential/admin writers must first use server-owned field allowlists and verified tenant/operation authorization; otherwise today's mass assignment can set the new status/version too. Hard-delete vs soft-delete/tombstone behavior and duplicate app-model schema definitions need explicit compatibility decisions. No standalone User schema patch is safe or recommended now.
- **Recommended isolation when writer integrity cannot yet be established:** separate independent scanner-principal authority record as detailed in STATUS-REVOCATION.md, with explicit approved scope cap and monotonic version outside generic User writes. This adds a collection/migration and conservative cross-document transition protocol but prevents generic legacy User-body assignment from directly reenrolling a disabled principal. It does not protect an enrolled principal's password until credential writers are fixed, nor justify enabling the scanner while other authority writers are untrusted.

Choose the authority owner, admin bootstrap, revocation guarantees and protected-writer boundary first. The smallest immediately reviewable code batch is recovery containment S01, not a speculative schema migration or adapter activation. No new field/collection, data backfill, version claim or operational migration was implemented; exact schema/provider/consumer hunks remain blocked pending this decision. Existing Batch A/A.1 hashes remain untouched.
