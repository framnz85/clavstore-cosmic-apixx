# Security, observability and privacy design

All Stage 10 helpers are standalone and inert. They open no files, listeners or telemetry connections and are not installed in route discovery. Authentication remains Stage 7's responsibility; the admission model accepts only a trusted post-authentication context from its caller and cannot verify a JWT or mint an authorization grant.

## New offline modules and their limits

- upload-bridge.js: validates bounded oriented RGB, encodes a dimension-preserving PNG using an explicitly supplied verified Sharp runtime, checks cancellation before/after native work and caps encoded bytes at ten MiB. It composes frozen Stage 2/7 public interfaces without editing them.
- review-contract.js: additional guard after Stage 7 strict response/current-catalog resolution. Requires scope, current authority, review-only/no-order/no-cart flags, explicit selection semantics, <=10 detections and no CROP_LIMIT_APPLIED. It preserves unknowns. It is not a substitute for Stage 7 authentication or untrusted AI validation.
- admission.js: disabled by default, one active scan, no queue, idempotent lease release, bounded process-local user+tenant token buckets (default burst three, one refill/minute, at most 128 keys). Rollback disable prevents new work and leaves an active lease until actual settlement. Invalid configuration fails closed. These values are proposed offline settings, not measured production rate limits. Normal error messages never expose tenant state.
- observability.js: explicit local sink only. Allowlisted event names, server-generated UUIDs, bounded stage milliseconds, validated model checksums/index generations and keyed tenant/actor pseudonyms. Raw tokens, headers, photos, OCR, product/customer text, source exception messages/stacks and raw tenant/user IDs are not copied. Unknown error codes become generic public errors. Sink failure returns recorded:false without echoing the exception; a production wrapper must count that failure through a safe internal metric without recursively logging secrets. Critical administrative audit failure should reject the admin action before mutation if durable audit is unavailable; the generic best-effort scan recorder alone is not a durable audit ledger.
- readiness.js: proposed offline evidence gates; missing real photographs/rights/human-held-out audit and insufficient/error-prone sample evidence block readiness. No result authorizes deployment, feature activation or cart changes.

No helper monkey-patches exports, mutates existing routers, auto-discovers models, injects DOM or changes legacy authentication. Explicit new function composition in tests does not register runtime behavior in the application.

## Production specification requiring later approval

Generate a public main request UUID at ingress; sign correlation/body/method/path/scoped identities through existing Stage 7 HMAC. Treat browser-supplied request IDs as untrusted and do not use them as authorization/idempotency proof. Use separate stable scanId and bounded submission identity with a server-owned tenant/user binding/TTL. Trace raw server request UUID across main/private service and map the browser-safe ID without exposing secrets. Index/model/policy pins must identify the actual loaded generation, never just the latest configured name.

Structured log events: scan_started/finished/failed, review_prepared and administrative snapshot/index request/approval/rollback. Fields: schema/time/request ID, pseudonymous tenant and operator, bounded operation outcome, error code, object/crop count, per-stage duration, approved model/checksum/index/policy versions, admission outcome and actual feature state. Stage 10's recorder emits reviewOnly=true because it is exclusively the offline review design, not a general production mutation audit. Add a new reviewed production wrapper rather than reinterpret this flag. Audit admin events must record actor, authorized role, requested scoped operation, old/new generation, approval reference, outcome and rollback correlation with durable access control and tamper evidence. The offline event helper is only a sanitization/schema proof.

Metrics should use low-cardinality stage/model/outcome labels: request counts, duration histograms, admission rejects, timeouts, crop truncation, model initialization, index age/recovery, unknown/correction/manual search rates, safe sink failures and process RSS/CPU. Do not use request IDs, raw tenant/product IDs, raw OCR or images as metric labels. Pseudonymized logs are still sensitive; separate logs from metrics, rotate the dedicated pseudonym key and restrict retention/access. Policy/catalog revisions may be added as bounded fields after schema review.

Apply an edge/IP/request-size limiter before expensive authentication/decoding, then authenticated tenant/user quotas and global native admission. Verify proxy trust before deriving client IP; do not trust X-Forwarded-For from the public internet. Process-local Stage 10 buckets do not coordinate multiple Node workers or hosts; use a separately authorized shared limiter or a single isolated gateway/worker first. HMAC replay storage, snapshot/index retention and administrative work queues similarly need multi-worker/restart designs. No Redis connection is introduced here.

Limits: one photo multipart field, <=10 MiB input and re-encoded output, <=24 million decoded pixels, bounded dimensions, single-frame JPEG/PNG/WebP, no arbitrary image URL fetching, ten object crops, bounded crop bytes/pixels/OCR regions, topK policy, <=200 authoritative IDs and Stage 7 1 MiB default/2 MiB maximum response. Cap each parser before allocating the full body; enforce ingress and post-decode limits, base64 canonicalization and signed exact bytes. Early private parser registration must not bypass capability auth, tenant scope, TLS verification or pinned addresses.

Photographs can contain people, addresses, receipts and payment information. Default: process in memory only, no photo/OCR logging or retention, no training reuse, no external analytics; clear browser object URLs/camera streams and drop server buffer references after completion/abort. Native buffers/GC do not promise immediate secure memory erasure. If a real evaluation dataset is retained, obtain usage rights/notice, minimize incidental personal data, store under scoped access with encryption, record retention/deletion dates and audit access. Set a documented short TTL/deletion process for diagnostics and longer-lived evaluation assets only with explicit owner approval. Image hashes may be sensitive linkage identifiers; keep dataset verification hashes out of general metrics/logs. Do not claim legal compliance from this technical design.

Deployment prerequisites: trust-separated keys with rotation, restricted service network/TLS, pinned model artifacts/dependency/runtime inventory, non-root worker, bounded filesystem/CPU/memory, no public reference-fetch SSRF, health/readiness separation and an emergency feature gate. Model/index unavailability must fail closed; never fallback to the old scanner. Real HTTP/TLS, proxy body/disconnect behavior, durable replay/audit, secure reference delivery and target-host capacity remain NOT VERIFIED.

## Rollback contract

Keep review flag and main/private service gates false before and after integration deployment. For rollback, disable public admission and UI, then cancel/drain active operations without releasing native slots prematurely; retire stuck workers via bounded watchdog. Revert only the approved route/startup/credential wrapper artifact to a signed known-good deployment, leave all legacy resources untouched, and keep new modules inert. Verify gated requests return FEATURE_DISABLED, old scanner routes/resources match previous hashes, no worker accepts new scans and no photo buffers/audit obligations are left indefinitely. Stage 10 tests verify only the isolated disable/drain model and unchanged frozen tests; actual deployment rollback is NOT VERIFIED. No cart/order migration exists in review-only mode, so there is no data rollback to execute. A later mutation phase needs its own reconciliation plan.
