## Mandatory role/membership integrity blocker

routes/user.js:42 registers user-create without auth middleware. controllers/user.js:707 onwards copies role from request body. routes/user.js:47 registers user-update with authCheck only; middlewares/auth.js:5–16 decodes without verifying a signature; controllers/user.js:963 forwards broad body updates into the user document. The displayed store-change check does not establish a field allowlist or authenticated role-management boundary. These are verified code paths, not executed exploits or claims about production reachability.

A secure scanner cannot claim trusted staff assignments solely because rows came from this DB while these write paths remain unreviewed. Correct scanner JWT verification does not repair source-data integrity. Audit/harden relevant identity/role/membership write boundaries and their callers under separate explicit scope before live wiring. No remediation patch is invented/applied here. No existing login/auth/user route/controller is altered by this review.

## Connection and import boundary

Production models import a connection bootstrap with createConnection and URI-bearing log templates. Do not import server.js, model files or dbconnect during preview diagnostics. Main server autoload calls each default router export; it does not call multi-scan.createRouter with getSessionSources. A helper existing on disk would not automatically wire that default route. Source-based future composition must receive the exact already-owned connection/model handles from a reviewed trusted startup boundary, never scan mongoose.connections by names, mutate exports, monkeypatch require.cache or open another connection as a fallback.
